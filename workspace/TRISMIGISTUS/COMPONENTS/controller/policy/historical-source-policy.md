# Historical Source Policy

Historical documents, old Plato references, lowercase Pluto paths, old adapter references, old agent-space paths, and retired instruction surfaces are provenance. They are not live routing/configuration.

## Current routing rule

New active routing may only use the current COMPONENTS layer, explicit TRIS packets, current project skills, and the single workspace authority file:

`/root/MW_CENTRAL/AGENTS.md`

## Authority clarity rule

Design names so any future operator can identify current law, historical provenance, deprecated material, and transitional surfaces without opening the file.

An authority-looking filename creates ambiguity. Therefore:

- Historical material must not keep live-law basenames.
- Retired authority-style files must be renamed to generic historical names.
- References to retired authority names must be sanitized before plaintext sanitation is considered complete.
- Archive receipts preserve original path/hash/size as proof, but active prose should label old material generically: `legacy instruction surface`, `historical setup notes`, `component governance history`.

## Evolution record rule

When documenting how the system evolved, write it as an explicit timeline with state labels:

- `HISTORICAL` — provenance only, never route from it.
- `TRANSITIONAL` — was live during migration, no longer current unless explicitly named.
- `CURRENT` — live authority/routing now.
- `DEPRECATED` — preserved for evidence, not instruction.

Do not make the reader infer status from age, folder, or model name.
